## 2. 项目概述

`Numeron` 是一款小体量、可重复游玩的单人自动战斗策略游戏。玩家在每局中通过招募单位、管理经济、组织阵容、选择开局 doctrine、触发羁绊与强化，在固定回合数内完成一场从开局到通关或失败的完整爬塔过程。

项目采用“产品外壳 + 共享 Rust 战斗运行时”的混合架构：

- `Next.js` 负责启动器、HUD、商店外壳、存档、战斗记录、总结页面与产品层交互。
- `Bevy / Rust` 负责棋盘、单位、战斗逻辑、回合推进、数值结算与可复用运行时。
- Web 与桌面版本共享同一套核心战斗逻辑。

当前项目目标不是做大而全的英雄池和长线运营，而是用一个可反复体验的垂直切片，验证以下三件事：

- 自动战斗的读图、构筑和节奏决策是否足够清晰。
- Web Shell + Bevy Runtime 的架构是否适合持续扩展。
- 小规模内容池是否已经具备可玩性、路线分化和复盘价值。

## 3. 产品定位

### 3.1 品类定位

- 品类：单人 Auto-Battler / 自走棋轻策略
- 核心体验：开局路线选择、回合内经济抉择、阵容羁绊构筑、自动战斗观战与复盘
- 运行平台：桌面原生、Web、PWA

### 3.2 体验关键词

- 易读
- 可复盘
- 有路线感
- 短局高重开
- 前端壳与战斗核心解耦

### 3.3 目标用户

- 喜欢 auto-battler 但不希望学习成本过高的轻中度策略玩家
- 习惯在网页或 PWA 中进行 10 至 20 分钟短局体验的用户
- 喜欢“边玩边看数据、边复盘边理解构筑路线”的系统型玩家

## 4. 设计目标

### 4.1 核心设计目标

1. 让玩家在开局 1 至 2 个回合内就感知到“路线不同，玩法不同”。
2. 让每一轮的经济、上人口、追对子、追羁绊之间存在真实取舍。
3. 让自动战斗不是纯结果播片，而是可通过战斗遥测、战斗记录和回合总结进行复盘。
4. 让当前小内容池也能通过 `starter doctrine`、`run modifier`、`augment` 和 `round event` 形成足够的局内变化。

### 4.2 当前阶段不追求的目标

- 联机 PvP
- 账号体系
- 云存档
- 深度 meta-progression
- 大规模羁绊网
- 装备系统
- 长线商业化系统

## 5. 核心卖点

### 5.1 开局 doctrine 决定早期路线

玩家在启动器中选择不同的 `starter doctrine`，会直接改变开局备战席、初始金币或血量，以及推荐构筑路线。这样开局不是单一模板，而是明确的策略起手。

### 5.2 自动战斗但强调“可读性”

每个单位都具备明确的目标规则、节奏触发和身份标签，羁绊、强化、战术指令和回合事件会共同影响战斗结果。玩家虽然不手操战斗，但仍能通过布阵、路线、上人口、经济和战术指令改变结果。

### 5.3 有指导性的 HUD 与 Build Pack

HUD 不只显示状态值，还会给出：

- 当前推荐 build pack
- 当前主羁绊进度
- 核心组件缺口
- 当前经济建议
- 当前路线判断

这降低了理解成本，也方便策划后续通过 UI 引导不同构筑思路。

### 5.4 每局可以复盘，不只是“打过了没”

战斗记录会保存：

- starter doctrine
- run modifier
- 选择过的 augments
- 有效羁绊
- 最终棋盘
- 回合历史
- 战斗遥测排名
- 经济收入构成
- MVP 标签
- 本局路线判断和失败原因

## 6. 核心玩法循环

### 6.1 单局循环

1. 在启动器中选择存档、语言、玩家名、触控偏好和 starter doctrine。
2. 启动运行时，进入本局。
3. 在准备阶段进行招募、刷新商店、购买经验、部署、撤回、卖出、重排站位、选择强化。
4. 根据当前经济、羁绊和 build pack 指引决定本回合投入策略。
5. 开始自动战斗。
6. 查看战斗结果、回合诊断、战斗遥测和回合历史。
7. 进入下一回合，重复上述流程，直到通关或血量归零。
8. 运行结束后生成 run summary 与 battle record，允许重开或继续查看存档内容。

### 6.2 局内决策层

玩家在单局中的决策主要分为六类：

- 开局路线：选择哪一种 starter doctrine
- 经济决策：攒钱、吃利息、刷新、上人口
- 阵容决策：追哪条 build route，优先补哪些 archetype
- 羁绊决策：先开 2 件套还是冲 4 件套 capstone
- 强化决策：是否围绕 augment 转型
- 战术决策：是否在战斗中启用 directive 改变 targeting 与节奏

## 7. 单局规则设计

### 7.1 胜负目标

- 玩家目标是在最终回合前完成爬塔通关。
- 当前最终回合为第 `8` 回合。
- 若玩家在第 `8` 回合击败敌方，则本局胜利。
- 若战败导致指挥官生命降为 `0`，则本局失败。

### 7.2 回合结构

每回合分为三个阶段：

#### 准备阶段

- 可进行招募、刷新、购买经验、部署、撤回、卖出、调整站位。
- 若当前回合触发强化草案，可在此阶段选择 augment。
- 若需要，可在准备阶段预设或替换战斗 directive。

#### 战斗阶段

- 玩家阵容与敌方阵容自动作战。
- 单位按自身目标规则与节奏规则进行攻击与技能触发。
- 战斗中可展示近期 combat feed、单位表现和局势读图信息。

#### 结算阶段

- 判定胜负。
- 结算金币、连胜连败、事件奖励和伤害。
- 记录回合历史、战斗遥测、round diagnosis。
- 若未结束，则进入下一回合准备阶段。

### 7.3 棋盘与部署规则

- 棋盘尺寸：`4 x 7`
- 玩家可部署槽位：`5`
- 敌方可部署槽位：`5`
- 默认备战席容量：`6`
- 默认初始等级：`1`
- 1 级部署上限：`2`
- 最大等级：`4`
- 等级越高，可部署单位越多

当前设计强调“小棋盘 + 少量上阵位 + 清晰单位身份”，避免信息爆炸。

### 7.4 经济系统

#### 基础数值

- 初始金币：`10`
- 商店基础槽位：`4`
- 买单位花费：`3`
- 刷新花费：`1`
- 购买经验花费：`4`
- 单次购买经验：`4 XP`
- 每回合基础收入：`4`
- 每回合被动经验：`1 XP`
- 基础利息上限：`3`
- 卖出返还：`2 x 星级`

#### 收入构成

每回合收入由以下部分组成：

- 基础收入
- 利息收入
- 连胜 / 连败收入
- run modifier 额外收入
- round event 额外收入

#### 利息规则

- 每 `5` 金币提供 `1` 利息
- 默认利息上限为 `3`
- 若获得 `Compound Interest`，利息上限增加 `1`

#### 连胜连败规则

- 连续 `2` 回合以上开始获得额外收益
- 连到 `4` 回合及以上收益更高
- 当前版本对胜败 streak 采取对称激励，鼓励玩家做真实节奏决策，而不是每回合都平均投入

### 7.5 等级与部署上限

- 最大等级：`4`
- 每级升级阈值：`4 XP`
- 购买经验与被动经验共同推动升级
- 升级后会提升部署上限
- 部署上限公式随等级增长，最高不会超过棋盘可部署槽位

当前版本中，上人口不仅影响单位数量，也影响本局节奏窗口，是训练日和中期投资的核心判断点。

### 7.6 商店系统

#### 基础规则

- 商店为单行展示
- 正常情况下显示 `4` 个候选单位
- 可手动刷新
- 可锁定商店

#### 特殊回合影响

- `High Roll Market` 会额外增加 `1` 个商店位
- `High Roll Market` 的首次刷新免费
- `Dawn Surge` / `Dusk Surge` 会让商店向对应 faction 倾斜

#### 设计目的

- 通过少量候选位放大“是否追对子 / 是否赌路线 / 是否立刻补强”的张力
- 通过事件和 modifier 让商店成为局内变化的核心来源之一

### 7.7 单位与星级成长

#### 单位内容规模

- 当前实现共有 `10` 个 archetype
- 每个 archetype 具备：
  - faction
  - role
  - 基础攻击与生命
  - 技能名称
  - 节奏说明
  - 目标规则

#### 星级规则

- 当前最大星级：`3`
- 单位存在重复合成路径
- 星级会放大单位基础数值，形成简单而清晰的成长曲线

### 7.8 羁绊系统

当前采用“两条 faction + 两条 role”的简单交叉羁绊结构：

- Faction：
  - Dawn
  - Dusk
- Role：
  - Vanguard
  - Skirmisher

羁绊阈值：

- `2`：基础成型阈值
- `4`：capstone 阈值

设计意图：

- `2` 件套负责给玩家中前期清晰反馈
- `4` 件套负责给玩家中后期明确路线目标

### 7.9 Starter Doctrine 系统

`starter doctrine` 是当前版本最重要的开局分化系统。它会同时影响：

- 开局备战席
- 开局额外金币或血量
- 新手引导文案
- 启动器预览
- 存档与 profile 偏好
- battle record 与 run summary
- build route 推荐逻辑

#### Doctrine 清单

| Doctrine | 中文名 | 开局效果 | 设计意图 |
| --- | --- | --- | --- |
| `balanced` | 均衡备战 | 无额外加成 | 默认稳健开局，适合观察商店后再决定路线 |
| `dawn-relay` | 黎明接力 | 指挥官生命 +2，开局偏 Dawn sustain | 强化保血和续航路线 |
| `dusk-raid` | 黄昏突袭 | 开局金币 +1，开局偏 Dusk backline | 强化前中期爆发节奏 |
| `iron-wall` | 铁壁开局 | 指挥官生命 +3，开局偏重前排 | 强化慢节奏、防守和拖回合能力 |
| `open-market` | 开放黑市 | 开局金币 +2，开局偏灵活后排 | 强化经济和快速转型能力 |

#### Doctrine 对应起手阵容

- `balanced`：Verdant Bruiser + Ember Medic
- `dawn-relay`：Verdant Bruiser + Lumen Sentinel
- `dusk-raid`：Ash Duelist + Shade Runner
- `iron-wall`：Iron Vanguard + Grave Warden
- `open-market`：Signal Ranger + Frost Oracle

### 7.10 Run Modifier 系统

每局 run 会携带一个 modifier，用于改变该局的宏观环境。其作用包括：

- 改变开局金币
- 改变备战席容量
- 改变商店偏向
- 改变额外收入
- 改变强化草案出现回合
- 改变 faction 攻防数值

#### Modifier 清单

| Modifier | 中文名 | 效果摘要 | 策略倾向 |
| --- | --- | --- | --- |
| `rich-opening` | 富集开局 | 开局额外 +4 金币 | 经济贪法与后期冲刺 |
| `thin-bench` | 短备战席 | 备战席缩到 4，但每回合额外 +1 金币 | 快节奏取舍 |
| `dawn-surge` | 黎明激涌 | 商店偏向 Dawn，Dawn 输出更高 | 续航与稳定前压 |
| `dusk-surge` | 黄昏激涌 | 商店偏向 Dusk，Dusk 爆发更强 | 速攻与斩杀 |
| `glass-cannon` | 高压脆皮 | 全体单位攻击更高、生命更低 | 抢杀竞速 |
| `augment-storm` | 强化风暴 | 强化草案出现更频繁 | 围绕强化命中转型 |

### 7.11 Round Event 系统

round event 是按回合触发的短期规则，用于制造局内节奏峰值。

#### Event 清单

| Event | 中文名 | 效果 | 策略价值 |
| --- | --- | --- | --- |
| `standard` | 标准回合 | 无额外规则 | 常规运营 |
| `training-day` | 训练日 | 买经验额外 +2 XP | 倾向上人口抢节奏 |
| `spoils-of-war` | 战利品回合 | 本回合获胜额外 +2 金币 | 倾向为赢投资 |
| `high-roll-market` | 高波动黑市 | 商店 +1 槽位，首次刷新免费 | 倾向追对子或追关键件 |

#### 当前回合分布

- 第 2、5 回合：`training-day`
- 第 3、6 回合：`spoils-of-war`
- 第 4、7 回合：`high-roll-market`
- 其他回合：`standard`

### 7.12 Augment 系统

当前版本共有 `6` 个 augment：

| Augment | 中文名 | 效果摘要 |
| --- | --- | --- |
| `compound-interest` | 复利协议 | 立即获得 6 金币，利息上限 +1 |
| `vanguard-doctrine` | 前线教范 | Vanguard 获得额外生命与减伤 |
| `skirmisher-drive` | 游击驱动 | Skirmisher 获得额外攻击并更偏向后排 |
| `dawn-pulse` | 黎明脉冲 | Dawn 获得额外攻击，节奏触发时治疗 |
| `dusk-pact` | 黄昏契约 | Dusk 获得攻击、生命和更强爆发 |
| `emergency-hull` | 紧急加固 | 指挥官立即回复 6 点生命，上限 30 |

设计原则：

- 一部分 augment 服务经济
- 一部分 augment 服务 faction / role 路线
- 一部分 augment 服务局内止血

### 7.13 战斗指令系统

玩家可在准备阶段预设、或在战斗过程中更换战术 directive，以改变自动战斗的优先级逻辑。

#### 当前 directive 清单

| Directive | 中文名 | 作用 |
| --- | --- | --- |
| `focus-backline` | 集火后排 | 偏向攻击敌方后排，可指定一路 |
| `hold-skills` | 保留技能 | 抑制节奏型技能触发，可指定一路 |
| `fallback-left` | 左翼后撤 | 让受保护一路更安全地拉扯 |

设计意义：

- 在不引入复杂手操的前提下，为自动战斗提供“观战中可调整”的轻战术层
- 让同一套阵容在不同敌情下仍有操作空间

### 7.14 Build Pack 指引系统

Build Pack 是当前 HUD 中的路线引导层，不直接改数值，但会影响玩家理解和学习成本。

#### 当前 Build Pack

| Pack | 中文名 | 核心思路 | 关联倾向 |
| --- | --- | --- | --- |
| `dawn-sustain` | 黎明续航 | 保血、叠回复、依靠稳定前排接管中后期 | Dawn / Dawn Relay / Iron Wall |
| `dusk-burst` | 黄昏爆发 | 用高爆发后排快速压低敌方主力 | Dusk / Dusk Raid / Open Market |
| `vanguard-bastion` | 前排堡垒 | 先成前排壳，再靠拖长回合取胜 | Vanguard / Iron Wall |
| `skirmisher-dive` | 游击切入 | 施压后排、快节奏转型、尽早兑现 tempo | Skirmisher / Open Market / Dusk Raid |

系统会根据以下信息自动给出推荐：

- 当前 doctrine
- 当前 active traits
- 当前已拥有核心 archetype
- 当前 build pack 分数

### 7.15 战斗遥测与复盘系统

当前版本引入了更完整的战斗遥测，用于提升复盘价值。

#### 遥测字段

- 输出伤害
- 承受伤害
- 治疗量
- 击杀数

#### 遥测用途

- HUD 中展示本回合表现排名
- 生成 battle record
- 支持总结页面中的 MVP 判断
- 帮助玩家理解“为什么赢 / 为什么输”

### 7.16 Run Summary 与 Battle Record

每局结束后会写入 battle record。当前记录项包括：

- 局号与回合
- 最终结果与分数
- starter doctrine
- run modifier
- 选过的 augment
- 当前有效 traits
- 最终阵容
- round history
- performance leaders
- 收入拆分
- 推断 build route
- 推断 econ plan
- MVP 标签
- outcome reason

设计目的：

- 把“可玩”提升为“可解释”
- 方便策划观察路线和单位表现
- 为未来远程同步、扩展模块和排行榜打数据基础

### 8.2 当前路线标签

系统当前会在局内推断以下 build route：

- 黎明续航线
- 黄昏爆发线

## 13. 当前版本的设计评价

从当前实现看，`Numeron` 已经不再只是“能打一局”的技术样例，而是具备以下特征的初级产品原型：

- 有明确的开局分化
- 有可读的中局经济决策
- 有足够清晰的小内容池身份
- 有战后复盘数据
- 有前端引导层帮助玩家理解路线

仍需持续优化的方向主要有：

- 数值平衡与路线强弱差距
- 单位技能视觉反馈
- 终盘决策的深度
- 不同 doctrine 与 modifier 之间的组合空间
- 更多真实 playtest 后的 economy 调优

## 14. 后续策划建议

### 14.1 优先级最高

- 补一轮真实 playtest 后的数值平衡
- 对每个 archetype 增加更鲜明的视觉反馈
- 强化 run summary 中的失败原因分类
- 将 build pack 从“建议层”继续推进为“更稳定的学习层”

### 14.2 下一版本可扩展方向

- 新增 2 至 4 个 archetype，补齐更多交叉构筑
- 新增 2 至 4 个 augments，增强经济线与转型线
- 扩展 doctrine 与 run modifier 的联动
- 加强敌方阵容模板差异，提升终盘识别度

### 14.3 长线方向

- 远程战斗记录与排行榜
- 可分享 replay
- 世界层 Agent 体系的外部扩展
- 异步挑战或 Ghost 模式

## 15. 结论

`Numeron` 当前最适合被定义为：

> 一款基于共享 Rust 战斗运行时构建的、强调开局路线分化、局内读图和战后复盘的单人 auto-battler 垂直切片。

当前策划重点不应转向堆内容，而应继续围绕以下主轴推进：

- 路线差异是否足够明显
- 经济与上人口窗口是否足够有张力
- 复盘信息是否足够解释胜负
- 小内容池是否能支撑高频重开

在这个基础上，项目已经具备继续扩展为更完整产品的结构基础。
